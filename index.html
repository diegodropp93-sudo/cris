Directorio de Trabajo (Working Directory)

Es donde editas tus archivos en Antigravity. Los archivos pueden estar en estado Untracked (nuevos) o Modified (cambiados desde el último commit). Todavía no están guardados en el historial de Git.

Configuración de Entorno

Primeros Pasos en Antigravity IDE

Prepara tu identidad de autor y arranca tu repositorio local en segundos.

03 / 09

1. Identidad de Usuario

Azure DevOps y Git requieren saber quién firma cada cambio. Configura tu nombre y correo antes de hacer tu primer commit.

Terminal Antigravity
$ git config --global user.name "Tu Nombre"
$ git config --global user.email "tu_correo@empresa.com"

2. Inicializar el Proyecto

Dentro de la carpeta de tu proyecto en Antigravity, inicializa la estructura interna de Git (crea el directorio oculto .git).

Terminal Antigravity
$ git init -b main
Initialized empty Git repository in C:/Users/usuario/proyecto/.git/
Integración Cloud

Conexión con Azure Repos

Vincula tu repositorio local con tu organización de Azure DevOps.

04 / 09
1

Crea el Repositorio en Azure DevOps

Accede a dev.azure.com/{tu-organizacion}/{tu-proyecto} y dirígete a Repos > Files para crear un nuevo repo o copiar la URL del existente.

2

Autenticación (GCM o Token PAT)

En Windows, Git Credential Manager abrirá la ventana de inicio de sesión de Microsoft automáticamente. Alternativamente, genera un Personal Access Token (PAT) con alcance Code (Read & Write).

3

Añade el Origen Remoto

Configura el alias origin apuntando a la URL segura de Azure DevOps.

Comandos de Vinculación

Terminal PowerShell / Bash
$ git remote add origin https://dev.azure.com/ORG/PROJ/_git/REPO
$ git remote -v
origin https://dev.azure.com/ORG/PROJ/_git/REPO (fetch)
origin https://dev.azure.com/ORG/PROJ/_git/REPO (push)
💡 Tip en Antigravity: Puedes pedirle al agente: "Ayúdame a clonar o vincular mi repo de Azure con mi PAT" y lo configurará por ti.
Operaciones Diarias

El Flujo de Desarrollo Diario (Add → Commit → Push)

Los 4 comandos fundamentales que utilizarás en el 90% de tu jornada de desarrollo.

05 / 09

1. Revisar Estado y Preparar

Comprueba qué archivos cambiaron con git status y agrégalos a staging:

Paso 1 & 2
$ git status
Untracked files:
  main.py
  config.json
$ git add .
Changes to be committed: [main.py, config.json]

2. Confirmar y Publicar en Azure

Guarda una instantánea con mensaje semántico y envíala a la nube:

Paso 3 & 4
$ git commit -m "feat: arquitectura base"
[main (root-commit) 9a3c8e1] feat: arquitectura base
2 files changed, 48 insertions(+)
$ git push -u origin main
To https://dev.azure.com/ORG/PROJ/_git/REPO
* [new branch] main -> main
Colaboración en Equipo

Estrategia de Ramas & Pull Requests en Azure

Nunca subas código directamente a main. Trabaja en aislamiento seguro.

06 / 09
🌿

1. Crear Feature Branch

Crea y cambia de rama de inmediato para tu nueva funcionalidad:

git checkout -b feature/login-azure
🚀

2. Publicar la Rama

Envía tu rama dedicada al repositorio en Azure Repos:

git push -u origin feature/login-azure
🔍

3. Pull Request en Azure

En Azure DevOps, abre el PR. Requiere aprobaciones de compañeros y validación por pipelines de CI/CD automáticos.

Reglas de Protección (Branch Policies) en Azure DevOps

Configura en Azure Repos: Mínimo 1 revisor requerido, Resolución obligatoria de comentarios y Compilación exitosa del pipeline antes del merge.

Resolución de Conflictos & Comandos Salvavidas

Mantén la calma cuando dos desarrolladores tocan las mismas líneas de código.

07 / 09

⚠️ Anatomía de un Conflicto

Cuando Git encuentra cambios incompatibles durante un git merge o git pull, inserta marcadores visuales:

<<<<<<< HEAD (Tu versión actual)
  apiKey = os.getenv("AZURE_KEY")
=======
  apiKey = vault.get_secret("AZURE_KEY")
>>>>>>> origin/main (Versión entrante)

Antigravity resalta automáticamente estos bloques con botones para Accept Current, Accept Incoming o Accept Both.

🛟 Comandos de Emergencia

git stash

Guarda cambios temporalmente sin commitear para cambiar de rama rápidamente.

git log --oneline --graph

Visualiza el árbol histórico de ramas y merges en una sola vista limpia.

git revert <commit-hash>

Deshace un commit público de forma segura creando un nuevo commit inverso.
