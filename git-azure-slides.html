    03 / 06
    👤

    1. Configurar tu Identidad Global

    Git estampa tu nombre y correo en cada commit. Esto es imprescindible para que Azure DevOps asocie tus cambios a tu cuenta de usuario corporativa.

    Terminal Antigravity (PowerShell / Bash)

    # Define tu nombre de autor visible

    $ git config --global user.name "Tu Nombre"


    # Usa el correo asociado a tu cuenta de Azure DevOps

    $ git config --global user.email "usuario@empresa.com"


    # Verifica que la configuración esté activa

    $ git config --list --show-origin

    📁

    2. Inicializar el Proyecto Local

    Convierte la carpeta abierta en Antigravity en un repositorio Git versionado. La rama por convención moderna debe llamarse main.

    Terminal Antigravity

    # Inicializa con 'main' como rama predeterminada

    $ git init -b main

    Initialized empty Git repository in C:/Users/usuario/proyecto/.git/


    # Crea un .gitignore para evitar subir archivos temporales

    $ echo "__pycache__/\n.env\nnode_modules/" > .gitignore


    # Consulta el estado del espacio de trabajo

    $ git status

    Nube & Autenticación

    Conexión Segura con Azure Repos

    Añadir el remoto y configurar credenciales con Git Credential Manager (GCM) o Tokens PAT.

    04 / 06
    🔗

    1. Vincular el Remoto 'origin'

    En Azure DevOps (dev.azure.com/{organizacion}/{proyecto}/_git/{repo}) obtendrás la URL HTTPS de tu repositorio. Enlázala a tu repo local:

    Configuración de Remoto

    # Conecta tu repo local al remoto de Azure Repos

    $ git remote add origin https://dev.azure.com/MI-ORG/MI-PROYECTO/_git/MI-REPO


    # Comprueba la URL de entrada (fetch) y salida (push)

    $ git remote -v

    origin https://dev.azure.com/MI-ORG/MI-PROYECTO/_git/MI-REPO (fetch)

    origin https://dev.azure.com/MI-ORG/MI-PROYECTO/_git/MI-REPO (push)

    🛡️

    2. Autenticación en Azure DevOps

    Azure DevOps ofrece dos métodos principales de autenticación segura:

  • Git Credential Manager (GCM - Recomendado): Se incluye automáticamente en Git para Windows. Al ejecutar tu primer git push, abrirá una ventana emergente de Microsoft para autenticarte con tu cuenta corporativa y MFA.
  • Personal Access Token (PAT): Si trabajas en entornos desatendidos o terminales sin interfaz gráfica:
    • En Azure DevOps: User Settings > Personal Access Tokens.
    • Alcance mínimo recomendado: Code (Read & Write).
    • Usa tu token como contraseña en el prompt de la terminal.
    • Flujo Diario (Daily Routine)

    El Ciclo: Status → Add → Commit → Push

    05 / 06

    Fase Local: Preparar y Guardar

    Audita tus cambios locales y confirma sólo los archivos que correspondan a una unidad lógica de trabajo:

    Terminal Antigravity

    # 1. Comprueba qué archivos han sido editados

    $ git status -s

    M main.py

    ?? azure_client.py


    # 2. Agrega al área de Staging

    $ git add main.py azure_client.py


    # 3. Confirma la instantánea con mensaje semántico

    $ git commit -m "feat(azure): conectar con cliente de blobs"

    [main 3f91a2c] feat(azure): conectar con cliente de blobs

    Fase Remota: Sincronizar con Azure

    Antes de publicar, siempre actualiza tus cambios locales con los que hayan subido tus compañeros:

    Terminal Antigravity

    # 4. Trae y fusiona los últimos cambios de Azure

    $ git pull origin main --rebase

    Current branch main is up to date.


    # 5. Publica tus commits en Azure Repos

    $ git push -u origin main

    Enumerating objects: 6, done.

    To https://dev.azure.com/ORG/PROJ/_git/REPO

    * [new branch] main -> main

    Colaboración Profesional & IA

    Ramas, Pull Requests & Antigravity IA

    Trabajo en aislamiento seguro y superpoderes de inteligencia artificial para tu código.

    06 / 06
    🌿

    1. Feature Branches

    Nunca trabajes directamente sobre main. Crea una rama dedicada para cada tarea:

    # Crea y salta a una rama aislada

    $ git checkout -b feature/auth-azure

    # Sube la rama a Azure Repos

    $ git push -u origin feature/auth-azure

    🔀

    2. Pull Requests en Azure

    En el portal de Azure Repos abre un PR hacia main. Configura Branch Policies para exigir:

    • Aprobación mínima de 1 desarrollador.
    • Resolución obligatoria de comentarios.
    • Pase exitoso del Pipeline de CI/CD.
    🤖

    3. Antigravity Pair-Programming

    Aprovecha el agente de Antigravity como tu copiloto en tareas de Git:

    • "Genera un commit semántico": El agente analiza tu diff y redacta mensajes descriptivos.
    • "Audita mi diff antes del push": Busca secretos filtrados, tokens o errores de sintaxis.
    • "Resuelve conflictos de merge": Ayuda visual para elegir la versión correcta.
